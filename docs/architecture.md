# 架构与兼容性约束

ai-switch 使用同一个 Python 包支持 Linux、macOS、Windows。公开 Git 仓库是唯一维护的源码；安装目录是构建产物，用户状态目录保存凭据、基准与备份，不参与打包。

## 模块职责

| 模块 | 职责 |
| --- | --- |
| `cli.py` | 参数解析、帮助、命令分发、错误脱敏和输出 |
| `manager.py` | 组装服务，保留原有方法签名；不实现业务流程 |
| `config.py` | 共享字段定义、值校验辅助函数和脱敏 |
| `profiles.py` | profile 查询、增删改、差异检测 |
| `baselines.py` | 原始 Micu 基准、命名基准、校验和恢复 |
| `storage.py` | 状态格式、配置锁、备份、写入日志和失败恢复 |
| `switching.py` | 切换、保存当前配置，协调 profile、客户端适配和存储 |
| `onboarding.py` | 保留原有 Micu/Aster 初始化策略和资源固定流程 |
| `diagnostics.py` | 状态与可选网络检查 |
| `launching.py` | 启动参数、环境清理、预检查、接管及原生续接 |
| `clients/` | Claude JSON/hook 与 Codex TOML 的捕获、渲染和专属字段校验 |
| `sessions/` | 列表、兼容副本复用、Codex 历史格式修复 |
| `platforms/` | 文件权限、文件锁、启动器解析、各平台进程接管 |
| `resources/` | 无凭据模板和读取 hook；通过包资源接口读取 |

服务采用组合。每项操作由明确的服务负责，服务之间通过具名属性调用；`Manager` 只保留兼容入口。存储层不依赖 CLI 或客户端服务；平台层不依赖 profile、会话修复或 CLI。客户端转换代码不提交文件、不结束进程。

Linux 使用独立接管后端；macOS 与 Windows 的公共检查流程复用 portable 后端，各自的系统调用保留在平台层。公共进程接口只负责选择后端，错误类型统一。

## 重构必须保留的行为

1. 已有命令、参数、默认值和退出码继续可用，帮助覆盖原有功能。
2. `state.json` 保持版本 1，用户目录位置和 profile 格式不变。
3. 读取旧状态、profile 和基准不自动迁移或重写文件。
4. 普通切换只替换受管理字段，保留 MCP、权限等公共设置；条件满足时恢复原始配置字节。
5. 固定基准的内容和校验规则保持不变，编辑、capture、删除 profile 均不覆盖固定基准。
6. 写入继续使用配置锁、私密权限、备份和日志；失败或中断仍可回滚、recover。
7. `--dry-run` 不提交配置、创建修复副本或结束进程。
8. 修复保留原会话，仍通过兼容副本续接；保留已有副本及其后续对话的复用规则。
9. 原生客户端决定会话写锁；接管仅在显式请求且核实目标后进行，不删除锁来绕过检查。
10. Windows 接管仍是结束单个进程，不能承诺保存尚未持久化的工作。
11. 启动器、配置、目录等预检查继续位于结束旧进程之前；客户端参数和凭据不交给 shell 展开。
12. 安装、打包和自动化测试不读取或携带真实用户状态；模板凭据继续为占位符。

## 实施与验证顺序

先冻结 1.9.1 的 CLI 和状态行为，再抽取存储、profile、基准、会话及启动服务；随后分离客户端适配、整理平台分发，最后调整安装和打包。每一步优先移动既有算法并保留执行顺序。

原有 152 项回归用例全部迁移到 `tests/`，故障注入改为针对新的实际依赖位置。新增的兼容检查应比较旧命令树、默认参数、转换结果以及已保存数据的恢复行为，避免只验证模块是否存在。

CI 覆盖三个平台的 Python 3.10/3.12，验证发布产物安装及资源可读；原生客户端测试连接本地模拟 API，覆盖跨 profile 续接和 Codex 接管。网络服务商可用性和任意未知历史格式不属于本次结构调整的验证结论。

旧工作区中的私人诊断记录继续留在仓库之外。旧开发副本可作为只读参考；今后的功能修复和发布以本仓库为准。
